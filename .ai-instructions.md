# AI Instructions — Visibill Project

## Zero-Flicker Rule (Critical)

All interactive elements (buttons, triggers, toggles) MUST follow these focus rules:

1. **Never use `focus:ring-*`** — use `focus-visible:ring-*` instead.
2. **Always add**: `outline-none ring-0 focus:ring-0 focus-visible:ring-1 focus-visible:ring-ring`
3. **Sheet/Dialog close**: always add `onCloseAutoFocus={(e) => e.preventDefault()}` to `SheetContent` and `DialogContent` to prevent focus flash on the trigger button.
4. **Popover triggers**: same `outline-none ring-0` treatment.

This ensures mouse clicks never leave a visible focus ring, while keyboard navigation (`Tab`) still shows the `:focus-visible` ring for accessibility.

## Flat Design Rule (Critical)

Visibill uses a **flat design language**. Hover-based shadows and elevation effects are **strictly forbidden**:

1. **Never add** `hover:shadow-*`, `hover:shadow-lg`, `hover:shadow-xl`, `hover:shadow-[...]`, or any hover-triggered `box-shadow`.
2. **Never add** `hover:scale-*`, `hover:-translate-y-*`, or any hover-triggered transforms that simulate "lifting" or "floating".
3. **Static shadows are OK** (e.g., `shadow-soft`, `shadow-sm` on cards) — they must **not change on hover**.
4. **Background color changes on hover** are fine (e.g., `hover:bg-primary/10`) — these are the primary hover feedback mechanism.
5. A global CSS safety net in `index.css` overrides any accidentally added `hover:shadow-*` classes to `box-shadow: none !important`.
