Az Aranyszabályok

🚫

Soha ne a main/develop ágon!

Mindig nyiss egy saját feature/... ágat. A közös ágakba kizárólag Pull Requesten keresztül kerülhet kód.

🔄

Minden reggel frissíts!

Mielőtt bármit csinálnál, húzd le a legújabb kódot, hogy elkerüld a felesleges konfliktusokat.

✅

Commitolj gyakran, de tisztán

A commit üzeneted legyen rövid, érthető és leíró. Pl.: "Új gomb hozzáadva a beállításokhoz"

💬

Kommunikálj!

Ha nagy módosítást tervezel, jelezd a csapatnak, mielőtt merge-elnél. Használj PR leírásokat!

2

A Napi Rutin

A. lépés

🌅 Munkakezdés – Frissítés

Frissítsd a közös alapokat, hogy a te gépeden is a legújabb kód legyen.

Bash 
git checkout develop
git pull origin develop
B. lépés

🌿 Új feladat indítása

Soha ne írj közvetlenül a develop-ba! Hozz létre saját munkaterületet egy beszédes névvel.

Bash 
# Hozz létre egy ágat (név legyen beszédes!)
git checkout -b feature/napi-feladat-neve
💡

Tipp: A branch név legyen beszédes és kisbetűs, szóközök helyett kötőjellel. Pl.: feature/kifizetes-gomb, feature/nav-szinkron-javitas

C. lépés

💾 Munka közben – Mentés

Ha elkészültél egy egységgel, commitold és pushold a saját ágadra.

Bash 
# Változtatások hozzáadása
git add .

# Commit rövid, érthető üzenettel
git commit -m "Rövid leírás a változtatásról"

# Feltöltés a GitHubra
git push origin feature/napi-feladat-neve
D. lépés

🔀 Összefésülés – Ha a feladat kész

A GitHubon nyiss egy Pull Requestet, várd meg a review-t, majd frissítsd a helyi develop ágadat is.

GitHub Pull Request 
# 1. Menj a GitHub repóba → "Pull Requests" → "New Pull Request"
# 2. compare: feature/napi-feladat-neve → base: develop
# 3. Kolléga átnézi → Approve → Merge
Bash – Merge után frissítés 
# Utána a saját gépeden frissítsd a közöst
git checkout develop
git pull origin develop

Konfliktuskezelés

⚠️

A CONFLICT nem hiba! Csak azt jelzi, hogy ugyanahhoz a sorhoz mindketten hozzányúltatok. Nyugodtan kezeld le az alábbi lépésekkel.

Megoldás lépésről lépésre

  1. Frissítsd a közöst a saját ágadon:
    git checkout feature/sajat-task
    git merge develop

  2. Javítsd ki a konfliktust:
    Az VS Code / Antigravity megmutatja a fájlt, amelyben a <<<<, ====, >>>> jelek vannak. Válaszd ki a helyes kódot, töröld a jeleket.

  3. Zárd le és pushold:
    git add .
    git commit -m "Konfliktus feloldva"
    git push origin feature/sajat-task

Hasznos Parancsok – Gyorsreferencia

Parancs Mit csinál?
git status Megmutatja a módosított, még nem commitolt fájlokat. Használd a legtöbbet!
git branch Kilistázza az ágakat, és megmutatja, melyiken vagy éppen.
git fetch origin Frissíti a tudásod a szerveren lévő ágakról (pl.: ha a kolléga új ágat csinált).
git log --oneline Commitok rövid listája – gyors áttekintéshez.
git diff Megmutatja a pontos módosításokat, amiket még nem adtál hozzá (git add).
git stash Ideiglenesen félreteszi a módosításokat (pl.: ha ágat kell váltanod).
git stash pop Visszahozza a félretett módosításokat.
git checkout -- . Elveti az összes nem commitolt változtatást. Óvatosan!
🔴

Figyelem: A git checkout -- . és a git reset --hard parancsok visszafordíthatatlanul törlik a nem commitolt változtatásokat! Mindig ellenőrizd git status-szal, mielőtt használnád őket.
