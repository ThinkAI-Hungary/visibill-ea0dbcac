🟡 Javítható: useTransactionData.ts — filterOptions

Jelenleg 500 sort tölt be kliens-oldali DISTINCT helyett. Javaslat — SQL DISTINCT RPC:

CREATE OR REPLACE FUNCTION get_transaction_filter_options(p_company_id uuid) RETURNS TABLE(currencies text[], types text[]) LANGUAGE sql STABLE SECURITY DEFINER SET search_path TO 'public' AS $$ SELECT array_agg(DISTINCT currency) FILTER (WHERE currency IS NOT NULL), array_agg(DISTINCT type) FILTER (WHERE type IS NOT NULL) FROM transactions WHERE company_id = p_company_id; $$;

3.3 transactions.matched_invoice_id — FK hiányzik

ℹ️ FONTOS A transactions.matched_invoice_id oszlopon nincs Foreign Key constraint. Ez a polimorf referencia-design tudatos döntés, de referenciális integritás szempontjából kockázatos. Ha a trigger (clear_transaction_match_on_invoice_delete) elromlik, orphan matched_invoice_id-k maradnak.

Teljesítmény hatás

✅ SELECT lekérdezésekre nincs hatással A frontend hookok nem végeznek JOIN-t a matched_invoice_id-n. Az useInvoiceData egyszerűen egy Set-be gyűjti az ID-ket és booleanként használja.

Hosszú távú javaslat (100K+ tranzakciónál): Egy match_target_table oszlop hozzáadása:

ALTER TABLE transactions ADD COLUMN match_target_table text; -- Lehetséges értékek: 'invoice', 'nav_invoice', 'salary' -- Ezzel a trigger elkerülheti a 3-as probe-ot
